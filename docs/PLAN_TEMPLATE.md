# Plan Template

> Copy this structure into `plans/NN-slug.md`. Keep it concrete and honest. ~400–800 words.
> Read `docs/HACKATHON_BRIEF.md` first and align to the judging criteria.

```markdown
# Plan NN — <Product name>

**One-liner:** <one sentence a judge remembers>
**Idea lane:** <the seed direction assigned to this plan>

## 1. Problem & target user
Who hurts, how badly, and why now. Be specific about the person.

## 2. The product
What it is and what the user does with it. The core loop in 3–5 steps.

## 3. Why it's novel (technical innovation)
The non-obvious mechanism. Why it's not a thin wrapper. What's hard and interesting.

## 4. Architecture & Claude Code / Multica role
- System sketch (components, data flow).
- Exactly where Claude Code and/or multi-agent orchestration is central.
- Key models / skills / tools used.

## 5. Build-day scope (the ~1-day vertical slice)
- MVP that actually works for the demo.
- What is explicitly OUT of scope for the day.
- Rough hour-by-hour cut (e.g. 0–2h, 2–5h, 5–7h, 7–8h demo polish).

## 6. The 2-minute demo
The exact on-stage script: what the judge sees, click by click, and the "wow" beat.

## 7. Evaluation / proof it works
How you'd show it's better than the baseline (metric, benchmark, or before/after).

## 8. Risks & unknowns
Top 3 things that could sink the build, and the mitigation/fallback for each.

## 9. Self-score (1–5 each, with one line of justification)
- Technical innovation: x/5 — ...
- Implementation quality (demo-ability in 1 day): x/5 — ...
- Potential impact: x/5 — ...
- **Total: xx/15**
```
